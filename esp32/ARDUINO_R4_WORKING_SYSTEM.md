The Arduino R4 WiFi sensor system is a fully operational air quality monitoring solution that continuously reads data from multiple sensors and transmits it to the SMOKi backend with robust offline storage capabilities using internal memory buffering. The system integrates four key sensors: the BME680 for temperature, humidity, pressure, and VOC measurements; the MICS6814 for gas detection including NO2, CO, and NH3; the PMS7003 for particulate matter monitoring (PM2.5 and PM10); and the ADS1115 as a 16-bit ADC for precise analog readings. Every five seconds, the system reads all sensors, packages the data into JSON format, checks WiFi connectivity, and either transmits the data via HTTPS to the backend API or stores it locally in internal memory buffer for later transmission.

The system operates in three distinct modes depending on network connectivity. In online mode when WiFi is connected, sensor data flows directly from sensors to JSON packaging to HTTPS transmission to the backend API. During offline mode when WiFi is unavailable, the system continues collecting sensor data but stores it in an internal memory buffer that can hold up to 10 records using a FIFO (first-in-first-out) system that automatically drops the oldest records when the buffer is full. When WiFi connectivity is restored, recovery mode automatically activates, reading all stored data from the memory buffer, sending each record sequentially to the API, and clearing successfully transmitted data while preserving any failed records for the next retry attempt.

The technical implementation successfully adapts the original ESP32 design to Arduino R4 WiFi hardware by utilizing WiFiS3.h library for R4-specific WiFi functionality, ArduinoHttpClient.h for simplified HTTP operations, internal memory buffer storage instead of external storage systems, memory optimization for the smaller 32KB RAM compared to ESP32's 520KB, and Serial1 for PMS7003 communication. The memory buffer recovery logic stores each failed transmission as a JSON string in an internal array structure, accumulates multiple records during extended outages up to the buffer limit, flushes all stored data sequentially upon reconnection, removes successfully sent data through buffer compaction, and persists failed records for subsequent retry attempts.

Key features include automatic backup that saves data in memory when WiFi is down, smart recovery that sends all buffered data when connection returns, real-time PMS7003 particle monitoring with checksum validation, WiFi resilience with auto-reconnection and retry logic, graceful sensor failure recovery, detailed serial logging for status monitoring including buffer status, secure HTTPS connections to the backend, structured JSON data payloads, multiple connection attempt logic, and efficient batch processing for offline data flushing. The system provides reliability with minimal data loss during network outages through intelligent buffer management, simplicity as a drop-in replacement for the ESP32 version without requiring external storage components, compatibility with the existing SMOKi backend, rich status feedback via serial console, scalability for easy deployment of multiple units, and proven operational status having been successfully tested and implemented.

This Arduino R4 WiFi implementation creates a robust, offline-capable sensor node that maintains data integrity during network interruptions using only internal memory resources, eliminating the need for SD cards or external storage while providing reliable recovery capabilities for continuous air quality monitoring in the SMOKi system through an efficient memory buffer that balances storage capacity with the Arduino R4's memory constraints.
